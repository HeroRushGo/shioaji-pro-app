## Contract

- Preserve the stream store's 50ms React notification batching. Candle arithmetic must consume each regular trade through onAnyTick, and each normalized index quote through a new additive onAnyIndexQuote callback. No React updates or drawing in raw callbacks; mutate a pure accumulator, then publish all changed buckets at most once per50ms timer. Dirty buckets include both sides of a minute boundary and late older edits; older edits use a full redraw to respect LWC ordering. The index has zero trade volume; regular and odd-lot streams remain separate. Simtrade/invalid prints never enter bars.
- Keep Taiwan wall-clock/right-close labels (daily calendar labels unchanged), session filtering, full timestamp precision and legitimate same-time multiplicity. Never deduplicate the raw event stream by timestamp or latest price. OHLC/extrema/volume are synchronous per print; indicators/React versions only advance on bounded draw or bar-close work.
- Stock13:30:00 closing auctions belong to the preceding right-close bucket. Shioaji's13:30 historical minute already includes that auction: after13:30, exclude today's final historical minute and rebuild its continuous prints plus auction from the raw prefix. This avoids counting the same auction in both history and tail, including daily/5m/15m views. Real2330 acceptance caught6801extra lots before this guard (61438instead of54637); the corrected daily total must match54637.
- Subscribe before requesting history and buffer up to50,000 real prints. Freeze the request-start closed-minute boundary; discard unclosed one-minute history. Aggregate its closed prefix to the requested interval, including a partial larger interval. Index KBars have no observation watermark or raw prefix API: retain complete target bars and resume zero-volume quotes at the next fully observed target bucket, with explicit incomplete status until then. This prevents older buffered quotes from rolling the historical close backward.
- Bootstrap the trade tail with the existing documented fetchLastTicks/LastCount API, starting512 and doubling to65,536 only until its oldest timestamp is strictly earlier than the closed-prefix cutoff. A short nonempty response alone cannot prove coverage (including a hidden server cap); it fails closed. The opening minute can therefore remain incomplete until a later refresh obtains an earlier witness. AllDay time bounds were experimentally ignored, so they are not used. Futures date lookup tries its next trading-date candidates around the night session as well as today, preserving clock dates from returned rows. Promise deduplication is in-flight only; completed tails must not become stale caches.
- Reconcile the REST tail with buffered/delayed live events using exact full-time+price+volume+tick-type multiplicity budgets, not a Set. Every unmatched print survives, including a late print before the REST watermark. Covered REST copies arriving after seed consume remaining budgets; further identical legitimate prints count after budgets are exhausted. This assumes matching REST/SSE records describe the same exchange print; no new exchange sequence identifier is invented.
- An empty REST prefix contradicting any observed real fill at/after the cutoff is not complete. Check both the quote known before loading and all raw fills observed during this generation; missing, stale or indicative initial snapshots cannot hide later pending trades. Such a contradiction discards the untrusted tail and waits for a fully observed bucket or manual retry.
- Nonempty REST must also include the exact real fill already known before the observer subscribed, when that fill is at/after the cutoff; otherwise a lagging prefix can silently omit known price extrema and lots. The13:30 auction at a fallback cutoff belongs to the excluded preceding bucket and must not revive it or clear incomplete status; normal postclose rebuilding starts13:29 and remains valid.
- Track the history's actual complete-through boundary independently of failure time. A request sampled09:03 cannot promote a partial09:05 target bar merely because its tail fails09:07. Fallback keeps only target bars proven complete at the history/raw-prefix observation boundary, then resumes at the future fully observed interval.
- History request cache identity includes the frozen minute and explicit revision, so changing views later cannot reuse an old open-minute prefix. Paging preserves the accumulated live tail. On overflow, unavailable tail or insufficient coverage, retain only complete target bars and wait from the next target interval boundary measured when failure is confirmed; reject earlier late prints and clear the untrusted pending queue. Display an explicit incomplete-tail status and allow the existing history refresh to retry. On live→down/stale, suspend callbacks and promises immediately, retain completed bars and mark continuity unknown. A new live connection epoch starts a fresh history/tail reconciliation generation. Never silently draw a partial volume as complete. All callbacks/timers are disposed on contract/timeframe/session/revision changes and unmount; stale promises cannot publish into the new generation.
